# ボルト有効長

`index.html`をChromeまたはEdgeで開く。サーバーやインストールは不要。アプリと資料は同じフォルダに置く。

公開アプリ: https://miyagoshigotono-lgtm.github.io/bolt-effective-length/

## GitHubと開発時の検証

GitHubリポジトリ`miyagoshigotono-lgtm/bolt-effective-length`で管理する。利用者の公開指示により、リポジトリとGitHub Pagesのアプリを一般公開する。取得したフォルダの`index.html`でも従来どおり起動できる。

`main`の自動テストが成功したときだけアプリを公開する。`pnpm build`で`dist/`へ必要なファイルを用意し、バックアップ・テスト・開発設定は配信に含めない。公開サイトでも入力や保存データは使用中のブラウザ内に保存し、サーバーへ送信しない。ローカル版で保存した内容は公開サイトへ自動移行しない。必要な構成はJSON書出し・読込で移せる。

開発時だけNode.js 24と、`package.json`指定のpnpmを使用する。次の手順で計算・DOM操作・SVG描画・添付ファイルを検証する。

```powershell
pnpm install --frozen-lockfile
pnpm check
pnpm test
```

GitHubのプルリクエストと`main`への反映時も同じ検証を行う。アプリの使用にはNode.jsや開発用ライブラリは不要。バックアップ・途中ファイル・テスト出力・端末内の保存データはGitHubに登録しない。ブラウザの画面配置・タッチ操作・印刷PDFの確認は、この自動テストには含めない。

## 入力

1. 片引き・両引きを選ぶ。
2. 「穴の位置」では、図の「柱105角」「柱から200」を押して数値を変える。左右の穴や穴名を押すと、座彫り・ボックス穴を選べる。
3. 図の座金や座金名を押して種類を選ぶ。厚さは資料値を自動設定。「その他の座金」だけ実寸を入力する。
4. 必要なら「寸法の詳細」を開き、桁の幅・高さ、ボルト深さ、最低かかり量などを変更する。保存名とメモは別の「保存名・メモ」に置く。

測定済みの有効長や、警告を見ながら木部の長さを調整するときは「有効長」へ切り替え、図の有効長の数字を押す。穴の位置から計算した値は切替時に引き継ぐ。

数値欄の右端の上下ボタンで、1回につき1 mmずつ増減する。手入力も従来どおり使え、277.5なら278.5のように小数部分を残す。数値欄でキーボードの上下キーも使用可能。図から開く入力欄・寸法の詳細・手入力できる座金寸法に共通。空欄や不正な値は勝手に補完せず、固定寸法は変更しない。

図の数値を押すと、図と並んだ編集欄を開く。背景を暗くせず、図や別の寸法・ズームも操作できる。広い画面では図の横、狭い画面では図の下に表示し、編集中は図の表示高さを抑える。変更するたびに計算と保存を更新。チェック・閉じるボタン・Escで編集欄を閉じる。手入力と1 mmボタンは従来どおり。空欄や不正な値の場合、結果は未計算となり、直前の図を修正用に残す。この図を計算済みの図として印刷・SVG保存はできない。

例：柱105角、左が座彫り28 mm、右が柱から200 mmのボックス穴なら、有効長277 mm。
両引き・角座金4.5 mmを左右1枚・最低かかり量10 mmを左右に指定すると必要長306 mm、候補315 mm、実際のかかり量は左右14.5 mm、ナットからの飛び出しは左右4.5 mmになる。同じ木部の片引きは必要長296 mm、候補300 mm、右のかかり量14 mm（ナット内10 mm＋ナット外4 mm）。

「かかり量」は座金の外面からボルト先端まで。ナットへのかかりと、ナットからの飛び出しの合計を左右別々に表示する。ナット内10 mm＋ナット外3.5 mmなら13.5 mm。座金厚さや左右の値を合算した数値ではない。上段の旧「座金・最低かかり量」はこの実際のかかり量に置き換えた。

最低かかり量は10 mm。ナット全厚10 mmへボルトが届くことを自動選定の条件にする。許容するナット外の飛び出しは0〜10 mmで、座金からのかかり量なら10〜20 mm。ナット厚さを最低かかり量に重ねて加算しない。手動で短い候補を選ぶと、不足と図上の実際の先端位置を表示する。

座彫り28 mm、箱穴58角、ナット10 mmは固定。「ボルト深さ」は材料の外ツラからボルト芯までの距離。初期52 mmで変更でき、有効長やボルト長の計算には加減しない。穴の底までの深さではない。

座金の寸法は資料の値を種類別に採用。「その他の座金」は実寸を入力する。片引きはナット形の頭と軸が一体になった絵で表示し、左に別ナットは追加しない。平座金の外形とボルト頭の実寸は未確定なので、実寸の図と区別する。詳しい測り方・式は`仕様.md`。

30/40 mm固定加算、暫定ルールの適用確認、構成プリセットは廃止。CADとの自動照合は行わず、利用者が目視確認する。

## カタログと出力

片引き29種類・両引き18種類を別々に登録。必要長以上の最小候補を選ぶ。手動で短い候補を選ぶと不足を表示する。

カタログの余りは有効長を変えず、かかり量へ回す。両引きは左右とも最低10 mmを確保して、なるべく均等に配分する。飛び出し10 mmちょうどまでは許容。10 mm超で警告する。条件内のカタログ長がない場合は、その旨と最小必要長以上の候補を表示し、有効長は変えない。警告時も候補・入力・保存・SVG出力・印刷を制限しない。利用者が有効長を調整すると即時再計算する。

入力を変えると即時再計算・描画。0.1 mm単位で計算し、小数第2位以下はエラー。画面・SVG・JSON・印刷で同じ結果を使用する。

入力画面は実寸比率の平面軸断面と、穴・座金・寸法の編集箇所を表示する。書出しSVGは金物の内訳とボルト深さの位置図も含む。位置図では材料の外ツラから芯までを示し、穴の底は描かない。桁の全長は入力していないので箱穴の先は省略線。狭い画面では文字を小さくしすぎないため図の中をスクロールする。ズームは実際の図のサイズを変える。

印刷はブラウザの印刷機能で行う。横向きはA4一枚、縦向きは二枚の構成だが、今回変更後のPDFページ数は未確認。不足・該当なしは確認チェックが必要。飛び出しの警告だけなら確認チェックは不要。長いメモ等は複数ページになる。

## 保存

作業中の入力は自動保存し、再読込で再開。計算前の途中入力も残す。取り消し履歴は作業中100件、再読込後は直近30件。

「保存」は同じ保存先を更新。「別の構成として保存」は別レコードにする。「保存済み」から開く・JSON書出し・削除・削除取り消しができる。組み合わせのプリセット登録とは別の共通ファイル操作。

JSONは形式6。保存結果を信用せず、読み込んだ入力を再計算する。旧形式3・4・5の有効な最低かかり量が3 mm以上・10 mm未満なら10 mmに引き上げ、変更を通知する。10 mm以上の指定・木部・座金・手動候補は維持し、途中入力の空欄や不正値を補完しない。必要長・自動候補は変わる場合がある。自動保存は移行前に原文を端末内へ退避し、名前付き保存やJSONファイルは読み込むだけでは上書きしない。

旧形式3の深さは「ボルト深さ」へ引き継ぐ。ただし旧画面の2つの深さが異なる場合は、勝手に選ばず読み込みを拒否する。旧形式1・2の計算は読み替えない。旧保存や壊れた保存は原文を書き出せる。

破損した保存一覧は「退避して一覧を再作成」で元データを残して再開できる。保存領域を使えない場合もJSON書出しは可能。ブラウザのデータ削除やフォルダ移動で端末保存を引き継げない場合がある。
