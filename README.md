# 計算ツール

`index.html`をChromeまたはEdgeで開き、上部の「ケラバカット」「ボルト有効長」「垂木けびき線」で切り替える。画面を切り替えても、入力・図の位置・取り消し履歴を維持する。計算の入力同士は連動させない。

公開アプリ: https://miyagoshigotono-lgtm.github.io/bolt-effective-length/

## 3画面の統合

- 入口は従来の公開URLと同じ。ケラバカットを先頭にし、初回もケラバから開く。`#keraba`・`#bolt`・`#kebiki`で画面を指定でき、次回は前回の画面を開く。
- ボルト本体は`bolt.html`へ移動。計算・図・保存キー・JSON形式は変えていない。同じブラウザ・同じ公開ドメインで使っていた保存内容を引き継ぐ。
- ケラバは`miyagoshigotono-lgtm/kerabaCut`の`7ce6e89`から取り込んだ。通常・瓦・発注書・印刷の処理と保存キーは原版と同じ。統合版では個別のService Workerと更新確認を停止し、入口の更新・オフライン保存を使う。元リポジトリの今後の変更は自動では取り込まない。
- 垂木は`ケビキ線電卓v2.html`を取り込んだ。計算式、タツ・カネの表示先、小数1桁の表示を維持。画面はケラバに合わせた配色・文字・入力欄とし、左に入力、右に大きな結果を表示する。狭い画面では上下に並べる。入力の現在の仕様は下記「垂木けびき線の入力」を参照。
- 3つの画面を別々の文書として保持し、CSS・入力欄ID・計算処理を混ぜない。切替時に読み直さず、未入力の数値を勝手に補完しない。
- 公開版はインストールに対応。初回にオンラインで読み込むと、3画面と資料をオフライン用に保存する。更新時のキャッシュ整理は、このアプリの範囲だけを対象にする。
- `js/site-assets.js`が配信・オフライン保存の共通一覧。更新する際は`sw.js`のキャッシュ版と、変更した画面・スクリプト参照の版も更新する。

## ケラバ図の勾配表示

ケラバ図の表題と勾配マークは、入力した勾配の小数を丸めずに表示する。1.33寸なら表題は「1.33寸」、勾配マークは横10・縦1.33とする。通常・瓦、画面・印刷で同じSVGを使用し、部材寸法の小数1桁表示と発注寸法の丸め方は従来どおり。

鼻隠しの水上・水下には「勾配カット(上部のみ)」「勾配カット(下部のみ)」「勾配カット(上下)」を選べる。下部のみは天端を水平、下端を屋根勾配とし、上部のみは逆にする。片側カットの長辺・短辺は実際の辺から測り、勾配落ちの寸法は切る側へ出す。下部のみの成に上下カット用の勾配落ちを追加しない。発注書は上部・下部を区別して一方加工へ載せ、下部だけのときは説明図も下部加工にする。

瓦で水下をカネ、水上を下部のみカットにして同じ天端の勾配線へ揃えるときは、両方の基準を「合板天端」、方向を「勾配に垂直」、オフセットを同じ数値にし、水上は「内寸」にする。40 mmなら双方に40を入力する。水上の水平な天端の内側が、水下の天端を延ばした勾配線に一致する。

合板の出は、水下・水上とも垂木先端から合板下端に沿って測る。カネの鼻隠しを合板天端から上へずらした場合も、鼻隠し内面と垂木天端の交点を基準にする。0 mmなら合板下端の先端が垂木先端に一致し、負数なら垂木先端より内側で止まる。

垂木欠きは「通常（母屋芯から）」と「テクノ（上角から10 mm）」を選べる。既定の通常は従来どおり母屋芯からの距離を入力し、テクノは母屋の水下側の上角から鉛直に10 mm欠く。テクノでは通常の数値欄を隠すが値は残し、通常へ戻すと再利用する。図の欠き寸法と母屋のカット寸法も選択した基準に合わせる。種類追加前の保存データは通常として読み込む。

図の作成に必要な入力が不足しているときは、その入力欄を薄ピンクで示す。「無し」の部材、通常タブで使わない瓦の条件、邸名等の任意項目は色付けしない。成の基準が未固定のときは、候補となる成と固定チェックを案内する。成を1つ以上10 mm以上で入力して固定し、必要な条件がそろうと色と案内を消して作図を再開する。入力値や保存形式は変更しない。

## 垂木けびき線の入力

上から「屋根の寸法」「部材寸法」の順に並べる。初回とリセット後は4項目とも空欄にする。各数値欄の右端の矢印から候補を選べ、同じ欄でそのまま自由入力できる。

- 桁寸：候補90・105・120 mm、自由入力1〜300 mm。
- 垂木成：候補60・90 mm、自由入力1〜300 mm。
- 屋根勾配：候補1.0〜5.0寸を0.5寸刻み。自由入力は0以上の数値とし、候補外の0.5寸や9寸、小数も受け付ける。
- 軒の出：0〜2000 mmの自由入力。

寸法の自由入力は小数も受け付ける。4項目がそろい、指定範囲内になるまで結果を「—」にする。範囲外を勝手に補正せず、その入力欄に理由を表示する。計算式・タツとカネの対応・mmの小数1桁表示は原版を維持する。

入力中の値は既存の専用キー `kebiki-line.input.v1` へ保存して再開できる。既存の作業データも引き継ぐ。入力がある場合のリセットは確認画面を出し、キャンセル・Escでは入力を変えない。確定すると4項目と結果を空欄へ戻し、次回起動でも空欄を維持する。ケラバ・ボルトの保存内容には触れない。

## ケラバの保存と共有

ケラバの上部に「保存」「開く」「リセット」を並べる。接続キー・パスワード・ログイン操作は不要。「保存」で名前を確認してクラウドへ登録し、「開く」でこのPC・このブラウザから保存した一覧だけを取得する。ローカルへのダウンロードは行わない。ボルト・垂木の保存方法は変更していない。

保存先はSites上の専用保存サービスとCloudflare D1へ変更した。アプリのソースと公開URLは従来のGitHub Pagesを継続する。ブラウザが初回の保存・読込時に推測困難な識別番号を自動生成してlocalStorageへ保持し、サーバーはそのハッシュでデータを分ける。利用者が番号を入力する画面はない。利用者の指示どおりPC・ブラウザごとに別の保存一覧とし、アカウント認証や別PC向けの共有リンクは設けない。ブラウザを閉じても同じ一覧を再開できるが、ブラウザの保存データを削除した場合や別プロファイルでは別の一覧になる。同じPC・同じブラウザを使う人同士は同じ一覧を使う。

保存は事前の同名データ読み出しを行わず、サーバー側で原子的に新規登録・更新を判定する。通常の新規保存と開いたデータの更新は1回の通信で完了する。同名の新規登録は保存せず、応答に含まれる版番号で上書きを確認する。

保存名を変えても邸名は変更しない。空欄や禁止文字は保存せず、キャンセルでは入力を変えない。開いたデータは同じ保存名で更新する。未読の同名データは上書きのチェックを入れるまで変更しない。読み出した版と違う場合は更新を止め、開き直しまたは別名保存を案内する。通信失敗でダウンロードへ切り替えたり、未確認の保存を成功と表示したりしない。

リセットは表示中の「通常」または「瓦」の寸法・勾配・物件情報・条件選択を空欄にする。表示する寸法線や縮尺は維持する。必要な寸法がそろうまで図・発注書は入力待ち表示とし、印刷も行わない。空欄へ既定値を補完しない。保存していない変更がある場合は「保存せずにリセットしますか？」の確認画面を出す。キャンセル・Escでは入力と図を維持する。保存・読み出し直後の変更がない場合はそのまま戻す。保存済みデータ、もう一方の屋根種類、ブラウザの識別番号は削除しない。再起動後も最後に保存・読込した内容と比較して未保存変更を判別する。

クラウドへ保存するのは表示中の屋根種類の入力だけ。小数・途中入力の空欄・既存のJSON形式 `format: keraba-project` / `version: 1` を維持し、読み込み後は入力から図・発注書を再計算する。「読み込み前に戻す」で入力・保存先・未保存状態を戻せる。従来のJSONは「開く → 以前のJSONを取り込む」で開いてクラウドへ保存できる。1 MB超や不正データは拒否し、通信中の変更は上書きしない。保存通信中の変更は未保存として残す。

作業中の自動保存は従来どおり端末内に残す。クラウドの保存・読込には公開URLとインターネット接続が必要。起動や通常の数値変更だけでは外部送信しない。保存先の識別番号をブラウザに記憶できない場合は、後から開けない保存先を作らず、理由を表示して入力を残す。

以前の専用GitHubリポジトリ `keraba-project-data` は既存データの保管用に残す。旧GitHub内のデータを新しい保存先へ自動移行しない。旧接続画面とAPIクライアントは廃止し、旧sessionStorageの接続キーも削除する。

保存サービスの管理用ソースはローカルの `.cloud-service/` とSitesの専用ソースリポジトリで管理する。Sites project ID は `appgprj_6ae7e8d85b5c8191944db9c8eeb247d0`、APIは `https://keraba-cloud-storage.workspace-010102.chatgpt.site/api/projects`。D1の所有者判別・入力上限・版を指定した更新はサーバー側でも検証し、利用者全員の一覧を返すAPIは設けない。

## 入力

1. 片引き・両引きを選ぶ。
2. 「穴の位置」では、図の「柱105角」「柱から200」を押して数値を変える。左右の穴や穴名を押すと、座彫り・ボックス穴を選べる。
3. 図の座金や座金名を押して種類を選ぶ。厚さは資料値を自動設定。「その他の座金」だけ実寸を入力する。
4. 図の下にある「左」「木部」「右」の条件ボタンから、穴・座金・桁の幅と高さ・ボルト深さ・最低かかり量などを変更する。保存名は「保存」を押したときに確認する。

PC画面は左に選択と結果、右に図、下にカタログ候補を置く。左右の幅制限を外し、図は縦横比を保ったまま表示領域へ自動調整する。図の中はスクロールさせない。「寸法の詳細」「保存名・メモ」「添付資料」と計算内訳の折り畳み欄は画面から外した。既存のメモや寸法値は保存・JSON・印刷に引き継ぐ。幅700 px以下では読みやすさを保つため縦に並べ、ページをスクロールして使う。

ボルトの左上はケラバに合わせ、「タイトル → 条件入力／パターン → 保存・開く・リセット → 条件」の順に並べる。青系の配色、文字ボタン、枠、余白と保存名確認の見た目を揃えた。取り消し・やり直しはタイトル横、別名保存・JSON読込・JSON書出は保存ボタンの下、印刷・PDFは図の上に置く。機能・計算式・保存形式・保存先は従来どおりで、ボルトの保存先は端末内のまま。通常のPC画面では図とカタログ候補を表示領域に収め、結果欄に収まらない警告等は左側だけスクロールする。

測定済みの有効長や、警告を見ながら木部の長さを調整するときは「有効長」へ切り替え、図の有効長の数字を押す。穴の位置から計算した値は切替時に引き継ぐ。

左をボックス穴にした場合は、穴の内〜内の有効長を直接入力する。「左端から左の穴まで（内側）」の入力と図の「左穴まで」は外し、この組み合わせで「穴の位置」からは計算しない。新しく穴の種類を変えた直後は有効長を空欄にし、前の木組みの数値を流用しない。もともと有効長を直接入力していた場合は、その値を維持する。

旧保存データが左ボックス穴・穴位置からの計算だった場合は、旧条件で計算できた有効長を直接入力へ引き継ぐ。未完成の旧条件は空欄から入力する。自動保存は移行前の原文を端末内へ退避し、JSONファイルや名前付き保存は開いただけでは上書きしない。退避先に書き込めない場合も旧入力を画面に復元し、自動保存の原文を保護する。

数値欄の右端の上下ボタンで、1回につき1 mmずつ増減する。手入力も従来どおり使え、277.5なら278.5のように小数部分を残す。数値欄でキーボードの上下キーも使用可能。図や条件ボタンから開く入力欄・手入力できる座金寸法に共通。空欄や不正な値は勝手に補完せず、固定寸法は変更しない。

図の数値・穴・座金・条件ボタンを押すと、押した場所のすぐ近くに変更欄を開く。通常は下、画面端では上や横へ避け、右端の固定欄には移動しない。図の幅・高さは変えず、背景も暗くしない。画面サイズ変更と再計算にも位置が追従する。変更するたびに計算と保存を更新。チェック・閉じるボタン・Esc・欄外の操作で閉じる。別の寸法は続けて操作できる。手入力と1 mmボタンは従来どおり。空欄や不正な値の場合、結果は未計算となり参考図を残す。穴の種類は最新の選択を反映し、位置が未確定のボックス穴は破線、有効長は「未確定」として区別する。入力や保存値を勝手に補完せず、この図を計算済みとして印刷・SVG保存することはできない。

ボックス穴は梁、座彫りは柱または梁側面として描き分ける。座彫り側の輪郭線を上下へ延ばし、柱の側面図・梁の平面図のどちらにも使える形にする。延長線は材が続くことの表示で、材長を示す寸法ではない。片引き・両引き、横・縦、画面・印刷・SVGで同じ描き方を使用する。

例：柱105角、左が座彫り28 mm、右が柱から200 mmのボックス穴なら、有効長277 mm。
両引き・角座金4.5 mmを左右1枚・最低かかり量10 mmを左右に指定すると必要長306 mm、候補315 mm、実際のかかり量は左右14.5 mm、ナットからの飛び出しは左右4.5 mmになる。同じ木部の片引きは必要長296 mm、候補300 mm、右のかかり量14 mm（ナット内10 mm＋ナット外4 mm）。

「かかり量」は座金の外面からボルト先端まで。ナットへのかかりと、ナットからの飛び出しの合計を左右別々に表示する。ナット内10 mm＋ナット外3.5 mmなら13.5 mm。座金厚さや左右の値を合算した数値ではない。上段の旧「座金・最低かかり量」はこの実際のかかり量に置き換えた。

最低かかり量は10 mm。ナット全厚10 mmへボルトが届くことを自動選定の条件にする。許容するナット外の飛び出しは0〜10 mmで、座金からのかかり量なら10〜20 mm。ナット厚さを最低かかり量に重ねて加算しない。手動で短い候補を選ぶと、不足と図上の実際の先端位置を表示する。

座彫り28 mm、箱穴58角、ナット10 mmは固定。「ボルト深さ」は材料の外ツラからボルト芯までの距離。初期52 mmで変更でき、有効長やボルト長の計算には加減しない。穴の底までの深さではない。

座金の寸法は資料の値を種類別に採用。「その他の座金」は実寸を入力する。片引きはナット形の頭と軸が一体になった絵で表示し、左に別ナットは追加しない。平座金の外形とボルト頭の実寸は未確定なので、実寸の図と区別する。詳しい測り方・式は`仕様.md`。

30/40 mm固定加算、暫定ルールの適用確認、構成プリセットは廃止。CADとの自動照合は行わず、利用者が目視確認する。

## カタログと出力

片引き29種類・両引き18種類を別々に登録。必要長以上の最小候補を選ぶ。手動で短い候補を選ぶと不足を表示する。

カタログの余りは有効長を変えず、かかり量へ回す。両引きは左右とも最低10 mmを確保して、なるべく均等に配分する。飛び出し10 mmちょうどまでは許容。10 mm超で警告する。条件内のカタログ長がない場合は、その旨と最小必要長以上の候補を表示し、有効長は変えない。警告時も候補・入力・保存・SVG出力・印刷を制限しない。利用者が有効長を調整すると即時再計算する。

入力を変えると即時再計算・描画。0.1 mm単位で計算し、小数第2位以下はエラー。画面・SVG・JSON・印刷で同じ結果を使用する。

入力画面は実寸比率の平面軸断面と、穴・座金・寸法の編集箇所を表示する。書出しSVGは金物の内訳とボルト深さの位置図も含む。位置図では材料の外ツラから芯までを示し、穴の底は描かない。桁の全長は入力していないので箱穴の先は省略線。画面の図は内容の範囲へ余白を詰め、横向き・縦向きとも全体を表示する。

印刷はブラウザの印刷機能で行う。横向きはA4一枚、縦向きは二枚の構成だが、今回変更後のPDFページ数は未確認。不足・該当なしは確認チェックが必要。飛び出しの警告だけなら確認チェックは不要。長いメモ等は複数ページになる。

## 保存

作業中の入力は自動保存し、再読込で再開。計算前の途中入力も残す。取り消し履歴は作業中100件、再読込後は直近30件。

「保存」は同じ保存先を更新。「別名保存」は別レコードにする。どちらも保存名を確認してから登録し、Ctrl+S・Ctrl+Shift+Sも同じ確認を通す。キャンセルやEscでは保存しない。「開く」から保存一覧を表示し、開く・JSON書出し・削除・削除取り消しができる。組み合わせのプリセット登録とは別の共通ファイル操作。

JSONは形式6。保存結果を信用せず、読み込んだ入力を再計算する。旧形式3・4・5の有効な最低かかり量が3 mm以上・10 mm未満なら10 mmに引き上げ、変更を通知する。10 mm以上の指定・木部・座金・手動候補は維持し、途中入力の空欄や不正値を補完しない。必要長・自動候補は変わる場合がある。自動保存は移行前に原文を端末内へ退避し、名前付き保存やJSONファイルは読み込むだけでは上書きしない。

旧形式3の深さは「ボルト深さ」へ引き継ぐ。ただし旧画面の2つの深さが異なる場合は、勝手に選ばず読み込みを拒否する。旧形式1・2の計算は読み替えない。旧保存や壊れた保存は原文を書き出せる。

破損した保存一覧は「退避して一覧を再作成」で元データを残して再開できる。保存領域を使えない場合もJSON書出しは可能。ブラウザのデータ削除やフォルダ移動で端末保存を引き継げない場合がある。
